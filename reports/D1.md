## 做了什么

搭好了 Next.js（App Router）+ Prisma + SQLite 的项目骨架：`prisma/schema.prisma` 建了契约里的 8 张表，另加一张内部表 `SessionRuntime` 存状态机状态和上下文。
`src/db/` 里每张表一个文件，函数入参/返回值都用契约类型，每行读出后过对应 zod schema，内容表默认只返回 `approved`，坏数据抛 `ContractDataError`。
`src/server/session.ts` 实现了 `handleEvent`、`startSession`，`app/api/session/` 下实现了三个接口。
另外写了 `db:seed`、`db:import`、初始 migration、接口说明和 26 个测试。

## 契约问题

1. `src/contracts/orchestrator.ts` 的 `SessionEvent` 只有 TypeScript 类型，没有对应的 zod schema。任务第 4 步要求接口在结构不对时返回 400，所以我在 `src/server/sessionSchemas.ts` 按契约类型逐字写了一份运行时校验（没有改契约）。建议总设计师在契约里补一个 `SessionEventSchema`，以后其他任务直接复用，避免两边不同步。

## 没做的和已知问题

- 任务 C1 还没合并，`src/server/deps.ts` 里的 `reduce`、`advanceChar`、`planDay` 是会抛“C1 尚未合并”的占位函数。C1 合并前，`POST /api/session` 会返回 500；`handleEvent` 的测试用假 `reduce` / `advanceChar` 覆盖。C1 合并后把该文件顶部三个常量改成从 `src/orchestrator/` 导入即可。
- 三个接口没有做登录、权限和限流，孩子编号直接取请求参数（任务明确不做）。
- `npm install` / `npm audit` 对当前依赖版本有安全告警（next、vitest、zod 等都有）。修复这些告警需要跨大版本升级，超出 D1 的任务范围；本次没有升级，建议合并后单独做一次依赖升级。
- `SessionRuntime.state` 从数据库读回时按契约类型断言，没有再写一份 `SessionState` zod 校验；`context` 只校验 JSON 合法性。它是内部表，不属于契约表。

## 建议

- 让契约给 `SessionEvent` 配上 zod schema，接口层直接 `parse`，可以删掉 `src/server/sessionSchemas.ts`。
- 给 `SessionContext` 也配 zod schema，`SessionRuntime` 读回时就能做完整校验。
- 内容导入可以考虑加 `--dry-run` 和逐文件错误汇总，现在遇到第一个坏文件就整体失败。
- 建议在 CI 里单独跑一次 `npm run build`（当前 `scripts/verify.sh` 只跑 typecheck 和 test），这样构建失败能更早发现。
- 建议单独开一个依赖升级任务，处理 `npm audit` 里的 next、vitest、zod 告警。
