## 做了什么

交付了 D2 模型调用层：`config/models.json` 配置八个运行时 Agent，全部指向 DeepSeek；`src/llm/config.ts` 用 zod 校验配置并执行“provider 必须是 deepseek”的产品红线；`src/llm/client.ts` 实现请求构造、图片消息、JSON 解析、schema 校验、一次输出重试、超时、5xx/网络重试、token 统计和 `onTurn`；`src/llm/offline.ts` 提供只给内容生产用的离线客户端。测试全部使用假 `fetch`，没有真实网络请求或真实密钥。

## 契约问题

无硬冲突。

补充说明：契约里的 `ModelConfig` 是八个运行时 Agent 的 `Record<AgentName, ModelRoute>`，没有定义离线配置（`draft` / `review`）的类型，也没有定义 `onTurn` 记录的类型。本任务按任务文件的要求，在 `src/llm/offline.ts` 内定义了 `OfflineConfig`，在 `src/llm/client.ts` 内定义了 `LlmTurnRecord`，没有修改或扩展契约文件。`createOfflineClient` 需要从两项离线配置中选一项，任务文件没有规定选择参数；本实现使用 `role: "draft" | "review"`，并写进了 `src/llm/README.md`。

## 没做的和已知问题

- 15 条验收标准均已完成，没有“未完成”项。
- `config/models.offline.json` 里的两个模型名是任务要求的占位值，负责人需要按自己账号可用的型号填写；不填不会被代码拒绝，但请求可能被厂商拒绝。
- 为遵守“整个 `call` 不超过 `timeoutMs` 两倍”，第二次请求在剩余预算不足 `timeoutMs` 时会缩短超时；剩余预算不足 500ms 时不再发起 5xx/网络重试。
- `onTurn` 记录按任务要求只包含 Agent 名、模型、三类 token、耗时和成功标记，不含 `sessionId`；调用方如需关联会话，用闭包捕获。
- `sleep` 是 `deps` 上的可选测试依赖，默认用真实 `setTimeout(500)`；它不改变对外契约。
- 未实现 `SpeechToText`、流式输出、Agent 提示词或 Turn 入库，这些都不在本任务范围内。

## 建议

- 如果后续任务需要稳定依赖 `onTurn` 记录或离线配置的类型，建议由总设计师把它们提升到契约里，避免各实现各自命名。
- 如果内容生产流水线需要更细的离线角色，可把 `role` 从 `"draft" | "review"` 扩展为可配置的字符串键；当前两项足够覆盖 C4 的起草/审校分工。

### 1. 红线在“拿到客户端”时生效

`src/llm/client.ts` 的 `createLlmClient` 现在先调用 `loadRuntimeConfig(deps.config)`，校验通过后才创建客户端。调用方手写配置对象或忘记先校验，都会在创建时同步抛错；错误信息包含出问题的 Agent 名。

测试（`src/llm/client.test.ts`）：

- `createLlmClient 自己守住红线 > 直接把含 openai 的配置对象传给 createLlmClient 时创建失败`
- `createLlmClient 自己守住红线 > 即使配置对象被 JSON 复制过也仍然检查结构与 provider`

### 2. `createRouteClient` 不再从 `client.ts` 导出

把核心实现移到 `src/llm/internal.ts`，文件顶部注明只允许 `client.ts` 和 `offline.ts` 引用；`client.ts` 只保留 `createLlmClient`，不再导出 `createRouteClient`。

### 3. 离线配置的 OpenAI 地址和超时

`config/models.offline.json`：

- `draft.baseUrl` 改为 `https://api.openai.com/v1`，拼出的地址是 `https://api.openai.com/v1/chat/completions`。

### 4. 上游响应无法解析时按服务端错误重试

`invalid_response` 分支已删除。HTTP 成功但响应体不是合法 JSON，或缺少 `choices[0].message.content`，现在返回可重试的服务端错误：等 500ms 重试一次，仍失败返回 `provider_error`；重试时消息数组保持不变，不再追加空的 assistant 消息。

已把 `main` 合并进 `task/D2`。`LlmTurnRecord` 不再在实现里定义，改为从契约文件 `src/contracts/llm.ts` 导入（项目现有模块用相对路径，等价于 `@/contracts/llm`）。失败时 `onTurn` 记录带上 `error`，成功时不带。
