## 契约问题

1. “无效输入也必须兜底”与“认字 usedCardFields 不能为空”在字卡缺失时无法同时真实满足。契约 schema 允许空数组：保守选择一句不知道、escalate、usedCardFields=[]，不编字卡或伪造引用；仍有有效字卡但其他字段无效时，只返回字卡原文。未改契约。
2. card.explain 首句也可能超过输出 say 的80字上限，或原文超过两句。先在超长/超过两句时取首句，首句仍超长只截前80字，不补知识或改写。报告和 README 明确这一保守取舍。
3. confusable 只给形近字列表，没有结构化的区别说明。只引用 explain 已有的区别；没有区别时只提示对照字形，不自行编部件、读音或字源。
4. DictationMark.expected 的 length(1) 按 UTF-16 计数，expectedWords 却未限定基本平面字符。兜底按现有契约的 UTF-16 单元顺序和索引构造；补充平面汉字无法在现有结构中作为一个正常字符表示，需总设计师明确后支持，不私改 schema。
5. “user 不包含字卡/参考要点”按不主动复制内容字段理解：字卡和 keyPoints 只放 stablePrefix，孩子历史原样放 user；孩子自己重复过的字词不做删改。
6. CharCard.status 可为 draft/rejected，ReaderInput 的 passage 不带审核状态；输入 schema 本身不保证内容审过。按架构由组装输入的外层只提供已审核内容；本任务不增加审核流程或内容护栏，未改契约。

## 没做的和已知问题

- 按任务不调真实模型；提示词遵守程度、字词判断、泄露答案、拒绝代写和采访维度去重仍须 C6 真模型评测与 C5 外层护栏验证。单元测试验证结构、请求分层、兜底和素材卡连续子串，不把提示词文本测试当成语义正确的证明。
- 视觉样例 URL 为 example.test 占位；C6 须按 expectation 制作合成图并替换 URL，不能直接把占位链接送去模型。
- 模型失败时不假装完成语义理解：阅读 wrap_up 用一句结束语，作文 interview 仅按卡片数量轮换细节问题、newCard=null。正常路径由提示词利用历史与卡片去重。
- 依赖安装提示现有锁定依赖有7项审计问题（3 moderate / 2 high / 2 critical），本任务未新增或升级依赖。
