## 契约问题

1. **缺少跨事件记忆字段。** `src/contracts/orchestrator.ts` 的 `SessionContext` 没有 `hasEssayToday`，也没有记录认读错误字、待听写字的专用字段。已向用户明确指出；用户回复“允许内部扩展上下文，契约文件保持只读”。据此仅在 `src/orchestrator/reduce.ts` 定义 `OrchestratorContext extends SessionContext`，包含 `hasEssayToday`、`understandChars`、`writeChars`。所有记忆显式放进返回的 `ctx`，不使用模块变量、对象身份或隐含编码。外层必须保留完整 `Transition.ctx`，不能按基础契约字段白名单裁剪。两个会话交错和每步 JSON 往返的测试覆盖了这一约定。
2. **缺少收尾完成事件。** `SessionEvent` 没有 `wrap_up_done` 或保存成功事件，无法只靠一次 `reduce` 同时返回 `wrap_up` 和 `ended`。保守地分两次调用：退出或学习完成先进入 `wrap_up` 并发出 `persist_session`；外层保存成功后以现有 `essay_step_done` 表示步骤完成，再进入 `ended`。该事件只有在 `wrap_up` 才有此收尾含义。重复退出仍留在 `wrap_up` 并请求保存；`ended` 吸收所有事件。建议总设计师明确增加专用完成事件。
3. **已掌握字与通用统计规则交叉。** `AdvanceChar` 规则6“mastered不再变化”和规则7“每次答对correctStreak+1；lastSeenOn总是更新”有冲突。采用阶段专用规则优先：已掌握字的阶段、排期、连续数、错误数全部冻结，只更新明确要求“总是更新”的 `lastSeenOn`。正确和错误重逢分别测试，没有新增学习记录或惩罚。
4. **理解答错没有明确规则。** 理解答错时保留 `understand`、错误数加一，连续数保持；会话里保留当前字并再次解释。只有两类复习答错明确清零连续数；认读和书写答错不擅自清零。退回理解时清空旧复习日期，避免遗留无效排期。
5. **认读错误的新字与字的阶段晋级必须同步。** 认读错误的新字按契约仍是 `recognize`，但会话要求将它送入 `understand`。不会补发虚构的正确结果或直接改 `stageOf`。外层每次执行 `persist_char` 后应通过 `advanceChar` 保存，并刷新下一次输入的 `stageOf`。处在 recognize 的字第一次理解答对只晋级到 understand，仍保留在理解队列；再完成一次真实的理解活动才可进入听写或两天复习。完整测试验证了该路径的每次持久化和实际字阶段。
6. **call_agent 的 payload 不是完整 Agent 输入。** `Effect.payload` 是 `unknown`，但 `SessionContext` 不包含 `CharCard`、ChildBrief、短文、作文原文及对话历史。按任务要求只输出已知字段（childId、字、步骤、照片地址、当前待听写字），不伪造卡片、提示词或空白作文。外层应在调用 Agent 之前补齐并用契约 schema 校验真正的输入；本任务不调用任何 Agent。`homework_captured` 事件也没有图片/口述内容，因此没有发出无法完成的 vision_homework 调用：由外层完成捕获并传回事件、随后传入确认清单。
7. **听写确认粒度与结束条件。** 仅接受恰好包含当前队列全部字且无重复的确认结果；其他结果作为非法事件忽略，不记录半份成绩。契约只有字而没有词语表，所以 `expectedWords` 使用单字词；不现编词语或从模型补知识。听写错误通过 `advanceChar` 退回理解，本轮仍按正常路径进入阅读/作文；跨会话如何继续 unfinished 的 understand/write 阶段，当前 `DailyPlan` 没有对应字段，留给总设计师补充，未擅自把它们改列为新字或到期复习字。

## 没做的和已知问题

- 模型、数据库、语音识别、护栏及界面是其他任务的范围，没有实现或引用其代码；`call_agent` 和 `play_audio` 由外层执行。
- 集成时必须按上一节保留扩展上下文、在每个持久化效果后刷新 `stageOf`，并在会话保存成功后发送收尾完成确认。当前的契约不能让一个只识别基础上下文字段、只执行完整 Agent 输入的外层无需适配地直接运行。
- 字的输入记录应属于同一个孩子且每字唯一，`stageOf`、`kindOf` 应覆盖当天计划；契约的 `PlanDay` 没有 childId 参数，无法自行判断多孩子混合输入的归属。
- 时长上限由外层发送 `time_up`，编排器不会读取时钟或根据未刷新的 `elapsedMinutes` 自行触发退出。
- 本任务没有解决跨会话中断续学策略；已按契约原样实现新字和复习字筛选，没有扩大范围。

### 更新后的状态转移表

“认字结束分支”表示：有作文进入 essay_interview 并请求 essay/interview，否则进入 reading_offer。所有接受的界面转移附加 show；ended 只有 end_session。每个字结果均先在返回上下文中用 nextStage 更新 stageOf，并发出对应的 persist_char，外层不补写阶段。

| 当前状态 | 事件/条件 | 下一状态 | 队列和效果 |
| --- | --- | --- | --- |
| 除wrap_up和ended外的任何状态 | quit / time_up | wrap_up | 清空活动queue，persist_session、show。 |
| idle | start | homework_capture | 保存hasEssayToday。 |
| homework_capture | homework_captured | homework_confirm | 显示待确认清单。 |
| homework_confirm | homework_confirmed | recognize（认读非空）；否则直接理解/听写/认字结束分支 | 认读=newChars+reviewChars去重；遗留understand进understandQueue，遗留write进writeQueue。 |
| recognize | recognize_result，仍有未认读字 | recognize | 一条persist_char、更新阶段、移除该字；新字无论对错及错误复习字加入understandQueue。 |
| recognize | recognize_result，认读结束 | understand；为空则dictation_play；都为空则认字结束分支 | 先处理已积累的遗留/新字/错字理解列表；有待写字时play_audio。 |
| understand | understand_done，第一次错误 | understand | attempts+1、persist_char、阶段仍understand，同字再解释一次。 |
| understand | understand_done，第二次错误 | 下个理解字；理解空则听写或认字结束分支 | attempts+1、persist_char，移出当前字，阶段仍understand，不加入writeQueue。 |
| understand | understand_done，正确 | 下个理解字；理解空则听写或认字结束分支 | attempts+1、persist_char、按nextStage晋级；移出该字，会写字加入writeQueue。 |
| dictation_play | dictation_played | dictation_capture | show。 |
| dictation_capture | dictation_photo | dictation_compare | call_agent vision_dictation，payload精确为imageUrl/chars。 |

| wrap_up | essay_step_done | wrap_up | 非法事件，返回原ctx，无效果。 |
| ended | 所有事件 | ended | 返回原ctx，无效果。 |
