# C7 派发前的设计清单

维护人：总设计师。2026-11-13，来自 C2/C4/C6 的独立验收；作为 C7-integration.md 的补充，不授权实现者自行扩大 scope 或修改契约。

C7 尚未派发。下一轮先由总设计师明确以下接口边界，再交独立实现者。这里记录的是尚未关闭的接线缺口，不是已经完成的能力。

1. **响应数据契约。** C2 的 src/ui/model.ts 目前定义本地 show.data 结构：清单 items；认读 char/可选 word；理解 approved card、say、ask；听写播放 approved cards；对照 imageUrl、chars、marks；收尾 learned/revisit。应由总设计师把确定的数据约定纳入共享契约，再让 C7 两端复用。ended + effects:[] 已合法，不能要求结束页必有 show。缺字卡的正常兜底也要有可渲染形状，不能伪造 approved 字卡。
2. **请求总预算。** C2 的 HTTP 总超时目前 8 秒，D2 一次调用即可能 8 秒且可重试，护栏也可能多次调用。需要协调客户端总超时和服务端整体预算，以假时钟/可控延迟证明合法的较慢响应可完成；不能只测立即返回的假模型。
3. **非幂等 POST 的响应丢失。** controller 重试会重新执行 start/coach/event 等操作。验收探针已证实 coach 可以推进两次。先确定稳定请求标识、服务端重复请求处理和状态恢复策略；不能把 D1 原子回滚等同于网络重放去重。若需要新增内部表或精确的 UI/db 路径，由总设计师先更新 scope；不允许把外层元数据偷偷写进 SessionContext。
4. **事务与外部 I/O。** 延续 D1 二次验收裁决：状态与学习记录原子提交；模型、护栏、图片外部操作在事务外。还要定义提交后效果失败或进程中断的恢复行为，避免重试重复记学习结果。
5. **照片边界。** C2 已在坏图/裁图失败时禁用判断并支持本地重试。当前 compare 状态没有服务端重拍事件；不要擅自跳回 capture。需要重拍时由总设计师先定义事件/状态含义。data URL 不落盘的约束也适用于未来响应缓存、幂等记录和日志，不能为了重放把原图存数据库。
6. **两端验收。** 既测真实数据库/编排器/Agent/护栏与假模型的服务端闭环，也验证响应能被真实 UI decoder 接受。当前 C7 scope 不含界面和数据库，设计完成后只增加必要的精确路径，并写对应回归；不把接口不兼容长期留作互相推诿。

原 C7 的 17 条标准、真实模型禁用、approved 内容来源、图片脱敏和完整失败兜底均维持，不降低标准。C7 验收通过后再写 C8–C11。
